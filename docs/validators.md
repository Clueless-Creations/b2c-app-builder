# Validator reference

Every validator the B2C App Builder repository ships, what it checks, and how to run it. This file is the full map; [CONTRIBUTING.md](../CONTRIBUTING.md) has the short version.

## How the pipeline works

`npm run audit` and `npm run audit:ci` both run [`tooling/run-audit.ts`](../tooling/run-audit.ts), the single orchestrator over the plan defined in [`tooling/lib/audit-plan.ts`](../tooling/lib/audit-plan.ts). Typecheck runs first, then every gate, with independent steps sharing a small concurrency pool.

```bash
npm install
npm run audit                       # full local pipeline
npm run audit:ci                    # full CI-equivalent locally (fast + heavy)
npm run audit:ci -- --lane presubmit  # ordinary PR / main-push gate
npm run audit:ci -- --lane fast        # historical cheap pool; full verification
npm run audit:ci -- --lane heavy       # fixture suites and engine e2e
npm run audit -- --list             # print the resolved plan without running it
npm run audit -- --only check:secrets
npm run audit -- --serial
npm run audit -- --concurrency 4
```

Two properties keep the plan honest:

- `check:package-parity` fails when a `check:*` or `validate:*` script is neither an audit step nor explicitly excluded with a reason, so a gate cannot be quietly dropped.
- `npm run test:validators` runs positive and negative fixtures, so a validator that silently stops catching its failure mode becomes an audit failure rather than a green build.

Steps marked `[ci-skip]` in `--list` are maintainer-only and skip automatically when their tooling is absent. `[repo-only]` steps run against this repo rather than a target app. `[presubmit]` marks the ordinary-PR allow-list. `[deferred]` / `[heavy-lane]` / `[fast-lane]` mark steps the other cadence skips.

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs **presubmit** on every pull request and push to `main`. The first Actions Presubmit job wall clock was **50s** (run [`34436428238`](https://github.com/Clueless-Creations/b2c-app-builder/actions/runs/34436428238)). Full verification (the historical fast pool, heavy shards, hosted worker, and builder console) runs on `workflow_dispatch` with `verification=full`, and when the Scope job fails so coverage cannot be deferred. Hosted and app jobs also run on ordinary PRs when the change matches fail-closed path prefixes in [`tooling/ci-lane.mjs`](../tooling/ci-lane.mjs) (Worker trees plus `catalog/`, `knowledge/`, shared contracts, root lockfile), not a live import graph. A green presubmit is not a full-audit pass; [`tooling/ci-aggregate.mjs`](../tooling/ci-aggregate.mjs) says so.

The `main` ruleset requires a pull request, blocks deletion, and blocks force-push. It does not require a status check, so renaming jobs does not need a ruleset bypass. If you later require a check, require `CI complete` (always runs; treats intentionally deferred jobs as skipped, not green) rather than `Audit (heavy)` or `Presubmit` alone.

## Running a gate against your app

Most validators take `--root`, pointing at the app repo the skill is launching:

```bash
npm run validate:launch-state -- --root /path/to/app
npm run check:security       -- --root /path/to/app
npm run check:revenue        -- --root /path/to/app
```

From an installed runtime copy instead of this repo:

```bash
cd ~/.codex/skills/b2c-app-builder
npm install
npm run validate:launch-state -- --root /path/to/app
```

### Structured `--json` output (D1, #32)

Every gate behind a `check:*` npm script accepts `--json` and, instead of its normal printed
report, writes one line of structured output and sets its exit code the same way it always did
(0 = pass, 1 = one or more errors):

```json
{ "pass": false, "failures": [{ "severity": "error", "rule": "PRODUCT_MD", "message": "Root PRODUCT.md is required as the rendered product index" }] }
```

`failures[]` entries carry `severity`, `rule` (the validator's own issue code, stable across
releases), `message`, and, when the validator supplies them, `path`, `location`, and `fixHint`.
`rule` is what to grep the validator's source for; the same string is what a fixture asserts on
in text mode.

Two agent-facing surfaces wrap this per-gate contract with the check's own name and npm script,
rather than making a caller remember which validator backs which name:

```bash
b2c check --list                                    # every check:* name, one per line
b2c check product-md --workspace /path/to/app --json
```

```json
{"check": "product-md", "command": "check:product-md", "pass": false, "failures": [...]}
```

Omit `--workspace` to self-check the skill's own shipped reference business, the same target an
unmodified `npm run check:<name>` gives a maintainer. Over MCP, the same verdict is available
through `b2c_status`'s `check` field (mutually exclusive with `cwd`, and requires `workspace`):

```json
{ "workspace": "my-app", "check": "product-md" }
```

`b2c_status`'s `isError` mirrors the gate's own exit code. A failing check is real structured
content, not a broken call, so read `structuredContent.pass`, not `isError`, for the verdict.

### Plain web app source roots

Use `--scan-roots` when a plain web app does not use the B2C App Builder business layout.
`--root` must identify the application root. Each `--scan-roots` value must be relative to that root.

```bash
npm run check:vibecoded-tells -- --root /path/to/web-app --scan-roots src
npm run check:vibecoded-tells -- --root /path/to/web-app --scan-roots src,app
```

The command fails when a named root is missing or contains no supported source files.
It also rejects paths or symbolic links outside the application root.
The command fails if one named root contains more than 5,000 supported source files.
Narrow the roots or run the complete surfaces separately.
These rules prevent a partial scan from returning a clean result.
The validator uses the application root to detect site shape and legal navigation.
It recognizes rendered `href`, router `to`, and literal Angular `routerLink` destinations.
For TSX and JSX, it follows exported function and class output.
It resolves same-file component output and ignores code after a terminal return or throw.
