# Superwall presentation and RevenueCat entitlement authority

Superwall owns placement presentation and treatment assignment. RevenueCat exclusively owns purchase, restore and active entitlements. The controller does not merge Superwall web entitlements or run a competing RevenueCat assignment engine. A purchase callback never grants access. Current RevenueCat entitlement readback does.

The host supplies public SDK keys and explicitly calls configure. This package performs no automatic provider operation. The native code is iOS only. Android and web selection must refuse. Local state tests do not establish SDK transport or provider behavior.

Preserve the anonymous exposure identity across sign-in as an explicit identity join. Keep original exposure and identified account separate; do not silently relabel past events. Logout removes exposure and invalidates callbacks from earlier identity generations. A restore result means the request completed, not that entitlement exists.

Pin Package.swift, Package.resolved, sources and test inputs in the extension snapshot. Record toolchain and output identity separately for every build. Sandbox and live proof remain missing until explicitly authorized current provider interaction supplies receipts.
