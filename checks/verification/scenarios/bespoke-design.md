# Bespoke design comparative evaluation

This protocol evaluates delivered products and knowledge transfer. Fixture success is not a product result. Follow U18/U19 and ARCH-11–13; keep product acceptance, benchmark judgment, provider proof, and repository conformance separate.

## Freeze before production

Record baseline and candidate revisions, model and reasoning settings, tool availability, reference inputs and rights, target platforms, budget, task prompts, and run order. Keep candidate guidance hidden from ordinary and baseline producers. Use a fresh context per run and separate producer and reviewer identities. Preserve failed outputs and actual usage. Do not infer costs from a rate card or invent missing telemetry.

Use three arms: A receives the same product brief and ordinary agent guidance; B receives the frozen existing builder through public entrypoints; C receives the candidate builder through the same public entrypoints. Use the same task, model, platform, asset/reference access, and effort ceiling. No maintainer coaching of C. Record any human intervention with its purpose and elapsed effort.

## Products and coverage

1. A quiet household document expiry and renewal helper for older adults.
2. A supportive, noncompetitive running routine for novices.
3. Club session and race analysis for experienced runners.
4. Local food discovery for travelers, with regional editorial detail and explicit provenance.

Each run delivers a working native slice with onboarding, core task, error and recovery, settings, and a selected offer state; a working mobile and desktop landing; and two store-creative concepts based on the actual product. No real purchase, account, personal data, deployment, or paid generation is needed for these local evaluation slices. Synthetic data must be labeled as such in the evidence and must not become public claims.

Run the twelve product/arm combinations. Repeat both running products in all three arms to assess same-category variation (eighteen total). Predeclare and record any resource-matched subset or ablation; it cannot replace the full comparison without an explicit change to the accepted evaluation scope.

## Review and decision

Assign anonymous output codes. Independent reviewers receive the common brief, required states, rendered artifacts and interaction evidence, but not the arm or producer rationale. Pairwise judgments explain audience fit, communication, composition, typography, identity coherence, function, accessibility, claim truth, and cross-surface execution. Missing evidence remains missing. Never average away a critical defect.

The candidate must be preferred to B on at least three of the four products, with no regression on the quiet utility or the same-category running pair. Required functional, accessibility, truthfulness, and evidence checks pass for every accepted candidate. Report disagreement and inconclusive comparisons. A beautiful hero cannot compensate for clipped text, broken recovery, or false claims.

Record elapsed time, actual tokens/cost when observable, iterations, defects, repair effort, and interventions per run. Compare cost per accepted result. Missing cost telemetry prevents a precise cost claim but does not become zero cost.

## Transfer and repair cases

Use held-out rendered examples containing: aligned but incorrect grouping; competing focal points; narrow-screen text overlap; curiosity hiding price; uniformly loud contrast; category-stereotyped palette; palette update changing warning meaning; ambiguous repeated control labels; changed font bytes; brand-kit drift in a derivative; unsupported claim; and a justified conventional exception. The independent reviewer must detect every seeded consequential defect, explain a suitable repair, and accept the valid exception. The producer repairs the artifact; a fresh review verifies the changed output. Vocabulary matching is not this evaluation.

## Separate 3D stress case

A fixed M brand instrument tests selected geometry, localized deformation and recovery, frame independence, pointer picking, controls, rendering, and export. Geometry, motion, render, and UI concerns remain separate. Record actual supported backend/version and observe forward/reverse interactions, different angles, reduced motion, fallback, and export. A 2D image does not prove 3D, and a declared renderer does not prove compatibility. Keep this result distinct from the four-product comparison.

## Evidence record

Keep run manifests, prompts, usage events, output hashes, captures, interactions, blinded judgments, failures, and repairs outside the public source tree unless sanitized and suitable for publication. The repository carries this reproducible protocol and meaningful harness fixtures. A results report must identify what was executed, what was inspected, and what remains unproven. Merge acceptance depends on the actual results under the accepted delivery plan.
