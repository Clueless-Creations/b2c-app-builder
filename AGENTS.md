# B2C App Builder Agent Guide

## Route by scope

Classify the target before reading broadly. Business work uses [`SKILL.md`](SKILL.md).
Reusable knowledge, recipes, or provider implementations use
[`agents/skills/b2c-contributor/SKILL.md`](agents/skills/b2c-contributor/SKILL.md).
Builder contracts, runtime, architecture, or agent-guidance maintenance uses
[`agents/skills/b2c-maintainer/SKILL.md`](agents/skills/b2c-maintainer/SKILL.md).
Business is an early exit: do not load maintainer or contributor curriculum for
an ordinary business task. Scoped routers own their procedures.

## Standing contract

This public repository owns the builder skill, runtime, contracts, catalog,
knowledge, and supported business surfaces. Keep secrets, live provider or
operator identifiers, private-repository references, personal addresses and
production configuration out of tracked files and public issues. Placeholder
hosted ids are intentional. Change authored knowledge or catalog sources before
regenerating projections.

Keep one logical owner for composition, execution, authority, evidence, truth,
and active state. Do not add a competing router, planner, context store,
execution journal, or evidence store. `product.yaml` owns accepted product
intent; `DESIGN.md` owns global design; reducer state owns attempts, evidence,
authority, pending work, and history; Git owns code and authored design history.
Generated files are projections, not authoring surfaces. Preserve founder
intent losslessly.

Provider guidance cannot silently select a provider or add requirements.
Availability is not selection, selection is not activation, activation is not
execution, and execution is not acceptance. Current provider, device, store,
runtime, and production claims require matching provider-native evidence.

An implementation request authorizes in-scope reversible repository work:
inspect, edit, run proportional checks, fix failures caused by the change,
regenerate affected output, review the diff, and complete required gates. It
does not authorize unrelated fixes, planning-only or review-only work, or a
material unresolved product, architecture, or scope decision.

Pause before access or credential changes, spend, pricing or legal decisions,
destructive actions, hosted deployment, store submission, publication, or
production release. A terminal command is not safe merely because it is local.
Guidance grants no authority and cannot manufacture an approval receipt.

Parallelize independent research, implementation, or verification when useful
with non-overlapping ownership. One coordinating agent owns shared-file
integration, Git and merge coordination, protected effects, and final
verification. Preserve genuinely independent review; do not invent a reviewer.

Use focused checks while iterating and all applicable required gates before
merge. Exact commands and cadence live in [`CONTRIBUTING.md`](CONTRIBUTING.md);
do not redefine or skip them. Report changed, verified, unknown, and next
decision separately. Do not route current work through Planes.

## Scoped owners

Business lifecycle, composition, mobile operation, and setup live behind the
business skill's conditional references. Maintainer architecture and provider
procedures live in the maintainer router and linked guides. Contributor rights,
provenance, and source adoption live in the contributor router. Task methods
and generated task skills remain with their existing catalog/rendering owners.
Thin host adapters route here and add only host invocation notes.
