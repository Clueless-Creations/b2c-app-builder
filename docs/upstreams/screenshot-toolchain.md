# Screenshot and capture upstream adoption

This maintainer workflow uses the existing source-adoption contract. It does not
install a screenshot editor or change a business. ADR-0005, ARCH-02/04/06/07/09/11
and roadmap U26 retain their owners; no public contract or execution mechanism
changes. The coverage report is a projection, not a second upstream registry.

`catalog/upstreams` owns exact reviewed commits, license evidence, source paths,
local consumers, limitations and review cadence. Knowledge manifests reference
that identity and record the adaptation. The contribution example under
`examples/contributions/screenshot-toolchain` records useful units and checks.
Do not maintain another editable version table here.

The adapted procedures are routed through existing store and capture workflows.
The new screenshot-toolchain reference loads on store screenshot production,
not on every business or research task. Upstream skill instructions remain
subordinate guidance. No installed executable or tool version was certified.

## Find other gaps

Run `npm run render:credits` and inspect `coverage-report.md`. It compares active,
bound knowledge source declarations with maintained upstream identities and exact
reviewed commits. It distinguishes untracked repositories, missing source links,
conflicts, and linked reviewed sources. Declared repository aliases are resolved
without guessing forks or transfers.

A URL is not evidence that code was incorporated. Review each gap before crediting
or adapting it. The report excludes non-GitHub sources, undeclared prose links,
package-manager and native dependencies, unbound knowledge, and the builder's own
repository. An empty report cannot certify the whole supply chain. There are
other review candidates, including design-method and recorder references; this
contribution does not silently classify them as supported integrations.

`check:credits` also checks this projection for drift. New declared sources become
visible through the same render/check process, without modifying a router or
installing another agent. The report and attribution history stay out of worker
briefs and the shipped knowledge corpus.

## Review updates

Use the existing commands from the repository or installed maintainer package:

```sh
b2c contribute upstreams --upstream parth-app-store-screenshots --json
b2c contribute upstream-check --upstream parth-app-store-screenshots --fetch --write --json
b2c contribute upgrade-plan --upstream parth-app-store-screenshots --json
```

The fetch is an explicit bounded metadata observation. The write records that
observation, not a new supported baseline. A source commit may change without a
release. Review the diff at the recorded source paths and preserve local
adaptations before proposing an upgrade. An absent release or host probe stays
unknown rather than becoming a compatibility claim.

For a Parth editor upgrade, compare old source, new source and local deck changes.
Keep custom themes, uploads, copy, locales and device decks. Inspect isolated and
connected exports independently. A new editor commit is not authorization to
migrate a running app or overwrite a working directory.

For native capture tools, verify the selected host, OS, architecture, toolchain,
actual executable and proof requirements before execution. A builder package pin
does not freeze a PATH binary or a Swift package dependency. A capture is not a
store upload or provider result.

Use `b2c contribute plan`, `check`, `evaluate` and `preview` for the normal reviewed
contribution. The commands do not execute unknown source during inspection. No
scheduled updater is enabled here; existing automation policy stays unchanged.
A genuinely missing execution or authority mechanism requires an architecture
discussion before implementation.

## Rights and notices

Preserve the source-specific license and applicable notices in adapted packages,
not only in the README. Retained notice coverage is checked for Apache-2.0 as well
as MIT. Never satisfy one source's requirement with a different project's notice.
The serve-sim license has no project-specific copyright line; its package metadata
identifies Evan Bacon. The records preserve that distinction rather than inventing
a copyright assertion.

No upstream template, font, mockup, binary or sample asset is redistributed by this
change. Future reuse must separately inspect rights, dependencies and required
notices. Credit records describe actual adapted procedures, not live support.

## Verification

Run `npm run test:fixtures -- screenshot-upstreams`, then the existing upstream,
contribution, notice and credits fixtures. Regenerate catalog, knowledge, package,
credits and evidence projections with the existing commands. `check:upstreams`
and `check:credits` must pass. Source changes remain subject to ordinary review.

These tests verify builder contracts, mappings, routing and notice delivery. They
do not launch an app, exercise upstream tools, judge rendered creative, prove
conversion improvement, or verify store acceptance. Those are separate business
execution and review obligations.
