# Failure Cards

Use failure cards when a blocker or recurring launch risk needs to survive the current conversation. They are small, explicit, and testable.

## Card Shape

```yaml
id: "posthog-person-property-missing"
severity: "high"
owner: "engineering-leader"
status: "open"
detected_at: "YYYY-MM-DD"
evidence:
  - "analytics/ANALYTICS.md"
impact: "Attribution cannot be used in cohorts, dashboards, or lifecycle messaging."
next_action: "Persist self_reported_source to PostHog person properties and backend profile, then verify."
validator: "npm run check:attribution -- --root ."
```

Store detailed cards in `operations/FAILURE_CARDS.md`. Link them from the affected lane's evidence and blockers in `state/business-state.json`; do not duplicate the cards in state.

## Provider Failure Cards

Use these as defaults and specialize them to the current app.

- **`doppler-config-name-and-credential-routing`** — (a) `doppler run --config` uses a name not confirmed from `SECRETS.md` or `doppler configs`; (b) `source` used on a non-POSIX env or credential file; (c) JavaScript template literals nested inside a double-quoted bash heredoc passed to `doppler run -- bash -lc`; (d) committed markdown contains awk/grep extraction snippet that prints a raw credential. Action: (a) Read `SECRETS.md` config map or run `doppler configs --project <name>` before any `doppler run` command — never guess; (b) replace `source` with `awk -F= '/^KEY=/{print $2}'` for single-value extraction; (c) use `doppler run -- node --input-type=module <<'NODE' ... NODE` (single-quoted heredoc) for JS that contains template literals; (d) remove extraction snippets from committed docs and replace with `doppler run --` command references; run `npm run check:secrets -- --root .`.
- **`doppler-docs-stale`** — Doppler setup or service-token instructions rely on memory. Action: Refresh official docs and local CLI help, then update `SECRETS.md` with docs/version basis.
- **`secret-routing-missing`** — new env var/key/webhook secret appears without `SECRETS.md` update. Action: classify public/server-only, provider location, command wrapper, CI injection, and rotation note.
- **`security-release-lane-missing`** — launch-ready claim exists without `trust/SECURITY.md`, threat model, scanner/review route, platform hardening, incident response, and accepted-risk proof. Action: create `trust/SECURITY.md`, render `trust/security-review.html`, route paid/free security tools, run `check:security`, attach scanner/review proof or founder-approved blocked route.
- **`security-tool-fallback-unapproved`** — Claude Security, Codex Security, GitHub Advanced Security, Snyk/Semgrep/Socket, MobSF Cloud, or commercial app-integrity route is replaced by a free route without approval. Action: stop, record route in `strategy/TOOL_DECISIONS.md` and `state/business-state.json`, ask for access/approval, then run the approved route.
- **`posthog-person-property-missing`** — attribution only emits event. Action: set person property, backend/profile persistence, anonymous-to-identified reconciliation, and proof.
- **`revenuecat-entitlement-unproven`** — products/offering exist but app access is not validated. Action: sandbox purchase/restore proves entitlement in app, RevenueCat, and backend/profile.
- **`app-price-vs-iap-confusion`** — store pricing work begins and no explicit confirmation exists that the app container price is Free and any Lifetime offer uses a NON_CONSUMABLE IAP SKU. Action: surface the distinction before pricing work; verify app container price is Free; verify a NON_CONSUMABLE IAP product exists for each Lifetime offer in `revenue/REVENUE_OPS.md`/`store/STORE_CONSOLE.md`; run `npm run check:store-console -- --root .`.
- **`stripe-webhook-unproven`** — Stripe checkout exists without webhook/idempotency proof. Action: verify webhook signature, idempotency, entitlement projection, and failure recovery.
- **`resend-template-unbranded`** — email templates ignore `DESIGN.md` or legal footer. Action: map brand tokens, sender, support reply-to, unsubscribe, idempotency, and provider log proof.
- **`sentry-unverified`** — SDK configured but no non-production event or alert proof. Action: send test event, verify release/environment tags, PII scrubbing, and alert routing.
- **`asc-name-fallback-unapproved`** — ASC CLI proposes fallback app name. Action: stop, record collision, ask founder, update brand/store/screenshots/revenue docs if approved.
- **`asc-command-guidance-stale`** — upstream ASC CLI or skill pack changes but references keep stale command families. Action: refresh Rork skill pack, local `asc --help`, official Apple docs, then update references/business/evals.
- **`motion-contract-prose-only`** — UI work ships celebration/gesture/shared-element/press surfaces while the motion acceptance criteria in `premium-mobile-craft.md` and `motion-craft-benchmarks.md` were cited but never applied — default eases on earned moments, no Reduce Motion fallbacks, one-sided navigation transitions, no Animation Hitches profile. Action: load both references before building governed surfaces; apply the two-family spring canon and the recipe checklists as checkable items; wire shared-element transitions on both sides or decline to a deliberate fade; verify Reduce Motion on device; record an Instruments Animation Hitches pass on the oldest supported device; run `npm run check:motion-contract -- --workspace-root /path/to/business-workspace` from the skill source checkout or installed runtime package for contract and active-workspace consistency.
- **`store-screenshots-raw-only`** — raw app captures are treated as final App Store screenshots. Action: create `SCREENSHOTS.md`, compose iPhone/iPad/App Store assets with copy overlays and design-system frames, validate dimensions/alpha/color space, attach visual QA, and keep upload founder-approved.
- **`app-preview-hook-missing-or-generic`** — an iOS listing has no app preview video (the autoplay-muted hook that precedes screenshots), or the hook/screenshots are generic — not built from the Asset Knowledge Brief (target user/problem, magical moment, Emotional North Star + Experience Card) or not produced through the screenshot ASO skill. Action: in `SCREENSHOTS.md`, fill the Asset Knowledge Brief and App Preview Video (Autoplay Hook) sections; storyboard the first 3–5s muted hook to show the defining product moment first with a poster frame that sells; route screenshots + preview through `ParthJadhav/app-store-screenshots` / `ios-screenshots` / `app-preview-video` with real footage and `reframe` for resolutions; verify truthfulness; run `npm run check:store-screenshots -- --root .`.
- **`apple-privacy-manifest-unproven`** — iOS App Store upload readiness is claimed without `store/APPLE_APP_STORE_REQUIREMENTS.md`, bundled `PrivacyInfo.xcprivacy`, required reason API audit, SDK manifest/signature inventory, Xcode privacy report, purpose strings, ATT decision, account deletion, review notes, and upload-warning status. Action: create the packet, reconcile official Apple docs with code/SDKs/App Privacy answers, add/verify `PrivacyInfo.xcprivacy`, run `npm run check:apple-requirements -- --root .`, and block ASC upload until resolved.
- **`source-registry-url-untracked`** — new external docs/tool URL appears without `source-registry.yaml` entry. Action: run `check:source-freshness -- --write-discovered`, review candidate source, and commit registry update.

- **`eleven-star-experience-missing`** — product/design/build work starts without `11_STAR_EXPERIENCE.md`, visual ladder, line of feasibility, and complete product experience. Action: create the experience contract, render `11-star-experience.html`, update `PRODUCT.md`, `state/LAUNCH_TRACE.md`, `DESIGN.md`, `product/ONBOARDING.md`, and `engineering/TECH_SPEC.md`.

- **`mobai-bridge-dropped`** — a build_run_sim or simulator relaunch invalidated the device registry and the agent retried stale UUIDs or skipped list_devices. Action: call list_devices after every build/relaunch; call start_bridge if device absent; never reuse a pre-build UUID.

Edge set: `laneDependencies` in `tooling/lib/launch-state.ts`; contract: `knowledge/orchestration/project-state.md`.
- **`change-cascade-incomplete`** — an app feature, copy, brand-term, pricing, or product change shipped without checking the surfaces it impacts (App Store listing/keywords/screenshots/captions, App Preview, in-app events, custom product pages, IAP/subscription display names + promo images, all localizations, landing page + meta/JSON-LD, SEO/GEO, lifecycle email, ASC review notes, RevenueCat product names, analytics event names). Action: run the Change Cascade Map in `knowledge/process/change-cascade.md`: enumerate the impacted surfaces for the change type, update each (or record why it is unaffected), re-render screenshots/listings where copy or UI changed, and reconcile the lexicon across surfaces before calling the change done. Record the result in `state/business-state.json` `lanes.post_launch_ops.changeCascade` and run `npm run check:change-cascade -- --root .`, which grades the entry against `knowledge/process/cascade-edges.yaml` and fails on any surface left unaccounted.
- **`ethics-guardrail-violation`** — any applied Experience Card (Commitment, Variable Reward, Perceived Effort Delay, Intent Mirroring), streak, scarcity, social-proof, or rating-prompt mechanism is shipped without a complete Guardrail Contract attestation block — or a forbidden phrase (fake scarcity, confirmshaming, fabricated social proof, fake effort, spend prompt inside a grief screen) is found in a live artifact. Action: run `npm run check:emotional-design -- --root .`; fix every error before claiming any emotionally persuasive mechanism is launch-ready; see `knowledge/experience/ethics-guardrail.md` Guardrail Contract and Non-Negotiable Prohibitions.
- **`zombie-app-no-kill-decision`** — the weekly ops rhythm runs indefinitely on a flat or declining app — MRR immaterial, cohorts deteriorating, founder hours out of proportion — and no day-30/day-90 checkpoint ever recorded a Kill, Hold, Or Scale verdict or put the continue-or-move-on question in front of the founder. Action: run the Kill-Or-Scale Review in `knowledge/operations/post-launch-operations.md` §9 at the day-30/day-90 retro checkpoints: assemble the evidence pack (MRR trend, cohort trend, CAC:LTV/payback, founder hours), present the verdict bands, record the founder's decision in `operations/LAUNCH_RETRO.md` and `lanes.post_launch_ops.kill_or_scale_decision`; `npm run check:post-launch -- --root .` fails a done lane whose retro has no verdict section.
- **`ethics-dark-pattern-in-artifact`** — a live artifact doc contains a non-negotiable prohibited pattern: countdown that resets on reload, fabricated user counts, fake loading spinner, paywall inside a streak-break screen, confirmshaming opt-out label, pre-ticked subscription box, or hidden subscription terms. Action: remove or redesign the pattern; add the appropriate card attestation block with `dark_line` and `guardrail` fields; run `npm run check:emotional-design -- --root .`; block ship until zero errors.
- **`emotional-design-system-missing`** — product, onboarding, core-loop, or paywall work proceeds toward build handoff while the 11-star target is 6-star or higher but no `EMOTIONAL_DESIGN.md` + `emotional-design.html` exist, so the experience has no engineered emotional layer and no card application map. Action: create `EMOTIONAL_DESIGN.md` from `business/product/experience/emotional-design/` and render `emotional-design.html`; map each magical moment to an Experience Card with a measurement event and bright-line guardrail; set `lanes.emotional_design`; run `npm run check:emotional-design -- --root .`; see `knowledge/experience/emotional-design-system.md`.
- **`variable-reward-without-ethics-guardrail`** — a Variable Reward, Streak, Scarcity, Urgency, or Social Proof card is applied without the full HIGH-tier attestation: `ethics_attestation`, `user_control_escape_hatch`, `counter_metric`, and the mechanism-specific truthfulness proof (`reward_variation_proof` / `streak_recovery_mechanism` / `scarcity_enforcement_proof` / `social_proof_truthfulness_proof`). Action: complete the attestation block for the card in `EMOTIONAL_DESIGN.md`; wire the counter-metric into the PostHog Dark-Pattern Watch dashboard; prove real variation/recovery in `engineering/PRODUCTION_READINESS.md`; run `npm run check:emotional-design -- --root .` until zero errors — this is a compliance veto, not a polish item.
- **`emotional-audit-prose-without-card-mapping`** — an emotional/UX audit returns narrative findings with no per-journey card mapping, no star-level, no counter-metric summary, and no concrete pathway-to-better-state, so findings cannot be integrated into the experience contract. Action: rebuild the audit in `EMOTIONAL_AUDIT.md`: enumerate every journey (Journey Discovery step), score each step through the six-lens review, map present/missing/misused cards (all four named cards or `experience_card:` blocks), and give each finding a sequenced pathway; run `npm run check:emotional-design -- --root .`.

## Closing A Card

A card can move to `resolved` only when:

- the fix is implemented or the lane is explicitly deferred/not needed
- evidence path or command proof is attached
- downstream docs and `state/business-state.json` are updated
- any founder approval is recorded

Do not close a card by saying the issue is "noted."

## Refresh

Give each card a `last_reviewed` date next to `detected_at`. Flag a card unresolved after 180 days as an ejection candidate. Retire a card once a deterministic validator catches the failure automatically. Move a retired card to a dated archive section below; never delete a card outright.
